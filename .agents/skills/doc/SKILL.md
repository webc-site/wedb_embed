# 文档写作与代码示例编写规范

本规范适用于本项目所有 README、技术文档与 `examples/` 示例代码的编写与审查。

---

## 1. 核心文档写作原则

### 1.1 排版换行与降低阅读压力
- **多换行与短段落**：<br>
  严禁大段长句文字堆叠。正文阐述采用短段落结构，单个自然段控制在 2~3 句话以内。<br>
  不同逻辑点与解释之间必须保留空行或使用 `<br>` 进行显式视觉换行。
- **列表项多层换行**：<br>
  无序列表项中若包含展开阐述、配置参数或性能对比，在列表标题与详细描述之间显式添加 `<br>`，<br>
  确保在 GitHub 网页端与移动端渲染时条理分明，降低读者认知负荷。
- **禁用引用块包裹正文**：<br>
  禁止使用引用块（`>`）包裹功能介绍与核心正文。<br>
  所有技术阐述应直接使用标准 Markdown 标题、段落和列表展开。

### 1.2 严禁添加引号
- **禁用各种形式的引号**：<br>
  正文描述、概念解释与功能介绍中严禁添加任何形式的引号（中文引号“ ”、‘ ’，英文引号" "、' '）。<br>
  例如：禁止写成“一线程一核心”架构或“工作窃取”模型，直接书写为一线程一核心架构、工作窃取模型。
- **代码与语法标记规范**：<br>
  代码标识符、结构体、Trait、方法名、参数与文件名一律使用反引号（`code`）包裹，<br>
  禁止用引号代替反引号。

### 1.3 客观严谨，克制专业
- **严禁浮夸与夸张形容词**：<br>
  禁用词汇：`极致`、`极速`、`强大`、`完美`、`震撼`、`无与伦比`、`神器`、`彻底`。<br>
  替代方案：用精确的底层架构、系统调用机制、P95 延迟数值、压缩率百分比与内存/磁盘实测数据说话。
- **坚决禁止空洞比喻与拟人修辞**：<br>
  严禁出现“瑞士军刀”、“收费站”、“快车道”、“高速公路”等生活化或空洞比喻。<br>
  直接从计算机系统底层机制阐述（例如：Socket 缓冲区、系统调用上下文切换、RESP 协议序列化开销、物理内存 RAM 容量边界、LSM-Tree 冷热分层与 LZ4 分块压缩落盘）。
- **逻辑链条清晰**：<br>
  采用清晰的技术逻辑链展开：现状物理瓶颈 -> 底层架构演进 -> 性能与资源收益。

### 1.4 标题与序号规范
- **中文标题保持纯净**：<br>
  禁止在中文标题后附加英文括号备注。<br>
  - ✅ 正确：`### 键值与字符串`、`### 保序变长整型编码`、`## 架构设计`<br>
  - ❌ 错误：`### 3. 键值与字符串 (KvOps)`、`### 哈希与字段级过期 (Hash)`
- **禁止硬编码数字序号**：<br>
  避免在子标题、正文说明列表与代码步骤注释中使用形如 `1.`、`2.` 等易因增删步骤而失效的数字序号前缀。

### 1.5 示例链接规范
- **使用绝对 URL 链接**：<br>
  所有 README 和技术文档中指向示例代码库的链接统一采用绝对 URL：<br>
  `https://github.com/webc-site/wedb_embed/tree/main/examples`<br>
- **链接文案格式**：<br>
  - 中文：`[点此查看完整示例代码（包含 16 种数据结构与多租户详细用法）](https://github.com/webc-site/wedb_embed/tree/main/examples)`<br>
  - 英文：`[Click here for more examples (all 16 data structures and multi-tenant APIs)](https://github.com/webc-site/wedb_embed/tree/main/examples)`
- **快速上手前置**：<br>
  - 依赖安装优先使用最简洁的 `cargo add <crate_name>`。<br>
  - 基础读写示例代码控制在 20 行以内，并在代码块下方附带上述绝对链接。

## 2. 示例代码编写规范

### 2.1 双语分离规范
- **严格禁止将中英文混在同一行**（如 `// 概述 / Overview`）。
- **结构必须为：先是完整的全英文段落，然后是完整的全中文段落**。
- **中文部分严禁附加任何英文备注**。
- **输出日志与终端提示**：双语日志整合到单个输出中，使用 `\n` 和空格缩进区分英文与中文。

### 2.2 文件开头模块级文档注释
- 每个示例文件必须以多行模块文档注释（`//!`）开头。
- 格式示例：

```rust
//! # Hash Map
//!
//! ## Overview
//! The Hash structure represents a collection of field-value pairs under a single key.
//! It supports individual field-level TTL expiration and subkey indexing.
//!
//! ## Use Cases
//! - User profile and account attributes
//! - Object entity representation
//! - Field-level cache invalidation
//! - Configuration dictionaries
//!
//! ---
//!
//! # 哈希表
//!
//! ## 概述
//! 哈希表结构用于在单个键下存储多个字段与值的映射关系。
//! 原生支持独立的字段级过期时间与高效子键检索。
//!
//! ## 使用场景
//! - 用户信息与账户属性存储
//! - 结构化对象实体映射
//! - 字段级独立缓存失效
//! - 配置字典与动态元数据管理
```

### 2.3 步骤注释双行结构
- 步骤注释分为两行：第一行为纯英文，第二行为纯中文（无英文备注、无数字序号）。
- 格式示例：

```rust
    // Basic get, set, and exists
    // 基础字段读取、设置与存在判断
```

### 2.4 依赖与代码规范
- 示例文件统一使用 `use anyhow::Result;`，`main()` 函数签名统一为 `fn main() -> Result<()>`。
- 字节切片参数统一采用 `b"key".as_slice()` 简洁表达。
- 断言比对优先使用数组字面量 `[...]`，避免产生不必要的堆分配。
- 保证无 warning、无 panic。

### 2.5 接口全覆盖与自动化检查
- 每个示例文件必须覆盖对应 Trait 或结构体所定义的全部公共接口方法。
- 编写完成后必须运行 `examples/check.js` 进行全量接口比对验证。
